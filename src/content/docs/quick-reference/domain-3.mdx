**`.claude/rules/` কোথায় বসে:** এই তালিকার শেষে নয়। `paths` ফ্রন্টম্যাটার ছাড়া rule-গুলো launch-এ `.claude/CLAUDE.md`-এর সমান অগ্রাধিকার নিয়ে লোড হয় — এগুলো একটিমাত্র বিশাল ফাইল ভাগ করার উপায়, কোনো "বেশি নির্দিষ্ট তাই জিতে যায়" স্তর নয়। `paths` থাকা rule শর্তসাপেক্ষে লোড হয়, যখন Claude সেই প্যাটার্নের ফাইল পড়ে। আলাদা করে: `~/.claude/rules/`-এর user-স্তরের rule প্রজেক্ট rule-এর আগে লোড হয়, তাই প্রজেক্ট rule-এর অগ্রাধিকার বেশি।

<ExamTrap label="মূল নিয়ম">

এটি load order, precedence chain নয় — কোনো ফাইল অন্যকে বদলায় না। দুই rule পরস্পরবিরোধী হলে Claude যেকোনোটি নিজের ইচ্ছায় বেছে নিতে পারে, তাই দ্বন্দ্ব উৎসেই সারান।

"বেশি নির্দিষ্ট স্কোপ জেতে" বা "user-level project-level-কে override করে" — এমন ডিস্ট্র্যাক্টর ভুল।

## `.claude/rules/` — শর্তসাপেক্ষ rule

`.claude/rules/`-এ থাকা ফাইল `paths` ফিল্ডসহ YAML frontmatter ব্যবহার করে শর্তসাপেক্ষে লোড হয়:

```yaml
---
paths:
  - "src/api/**"
  - "src/middleware/**"
---
Always validate authentication tokens before processing API requests.
Use structured error responses with proper HTTP status codes.
```

Rule লোড হয় কেবল তখনই, যখন Claude Code সেই glob প্যাটার্নের ফাইল নিয়ে কাজ করে। এতে অপ্রয়োজনীয় rule কনটেক্সট উইন্ডো জুড়ে জায়গা খায় না।

Skill-এর বৈশিষ্ট্য:

- `allowed-tools` — পরীক্ষার গাইডে এটি skill-এর টুল অ্যাক্সেস সীমিত করার কথা বলে, আর পরীক্ষার প্রত্যাশিত উত্তরও সেটিই। বর্তমান Claude Code-এ (জুলাই ২০২৬) এটি তালিকাভুক্ত টুল আগেই অনুমোদন করে, যাতে permission prompt ছাড়াই চলে; নিষেধ করার কাজ করে `disallowed-tools` আর permission deny rule।
- `context: fork` — ফর্ক করা কনটেক্সটে চলে, যাতে skill চালানোর ধুলো মূল কথোপকথনে না লাগে।

Skill হলো পুনর্ব্যবহারযোগ্য capability module — "test চালাও", "staging-এ deploy করো" জাতীয় workflow, যার টুল অ্যাক্সেস frontmatter-এ ঠিক করা।

Command `/` প্রিফিক্স দিয়ে চালু হয়। এগুলো template — আগে থেকে লেখা প্রম্পট, যেখানে `$ARGUMENTS` placeholder দিয়ে ব্যবহারকারীর ইনপুট ঢোকে।

**Skill থেকে পার্থক্য:** command আর skill একই সিস্টেমে মিলে গেছে — দুটোই `/command` বানায়। Command হলো একটি সমতল `.md` ফাইল (প্রম্পট template, `$ARGUMENTS` চলে); skill হলো একটি ডিরেক্টরি, যার entry point `SKILL.md`, সাথে বাড়তি ফাইল, frontmatter configuration আর প্রাসঙ্গিক হলে স্বয়ংক্রিয় invocation।

- `PreToolUse` hook, `/prod/` পাথে `rm` আটকায় → deterministic, ভাঙা যায় না

## ফিডব্যাক কৌশল

- গদ্য বর্ণনার চেয়ে বাস্তব উদাহরণ জোরে। যে কোডটা চান, সেটাই দেখান — বর্ণনা করা অনুচ্ছেদ নয়।
- নির্ভরশীল fix একসাথে এক মেসেজে batch করুন, যাতে মডেল একবারে সব সীমাবদ্ধতা দেখে। স্বাধীন সমস্যা এক-এক করে ক্রমান্বয়ে সারান।
- **স্বাধীন review session:** যে session কোড লিখেছে, সেই session-এ কখনো review করবেন না। লেখার সময়ের reasoning bias থেকে যায়। Review-এর জন্য নতুন session নিন।
- **Severity calibration:** কোনটি critical আর কোনটি ছোটখাটো style nit, তা উদাহরণ দিয়ে দেখান। Calibration ছাড়া মডেল সব সমস্যাকে সমান গুরুত্ব দেয়।

## Permission ও সুরক্ষা

- Permission টুল-স্তরে নিয়ন্ত্রিত — নির্দিষ্ট কোন টুলে অনুমতি দেবেন আর কোনটায় দেবেন না, সেই সিদ্ধান্ত।
- Subagent-এর টুল সেট তার `AgentDefinition`-এর `tools` ফিল্ডে বাঁধা; skill `allowed-tools` frontmatter ব্যবহার করে।
- Least privilege-এর নীতি: প্রতি agent/skill কেবল দরকারি টুলেই হাত দেবে।
- প্রজেক্ট-স্তরের setting (`.claude/`) কমিট হয় ও শেয়ার হয়; ব্যক্তিগত setting (`~/.claude/`) হয় না।
